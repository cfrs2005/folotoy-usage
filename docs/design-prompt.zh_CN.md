# FoloToy 用量仪表设计提示词

## 研究依据

- [Wear OS 小屏原则](https://developer.android.com/design/ui/wear/guides/get-started/design-for-wearables/principles)：聚焦关键任务，缩短操作，展示相关信息，并处理离线状态。
- [Anthropic 设计提示词](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md?plain=1)：从具体产品建立视觉语言，让结构表达信息，并对结果做反向检查。这是设计参考，不把网页特效照搬到 MCU。
- 渲染依据是本地锁定的 LVGL 9.5 实现：RGB565 分块绘制，固定内存，不申请完整帧缓冲。

## 本次工作提示词

### 产品判断

设计一台桌面仪表。主人在两秒内应能分清 Claude 与 Codex 的额度、各自的重置时间，以及这些数据是否新鲜。保留头像、名称、本地年月日和时间；首页同时有两个平台，用量单独一页。画布只有 240×320，输入只有三个实体按键。不要添加假触屏按钮或底部菜单。

### 视觉判断

每个平台用一条紧凑的色带标识。5 小时与 7 天额度并排，两个平台中相同的数字放在相同位置。数字用独立的等宽字体，中文标签更安静。数值大、周期明确、重置时间次要。每条线和每种颜色都必须表达身份、数量或状态；移除抢夺注意力的装饰。

### 硬件判断

使用原生 LVGL 对象和分块渲染。复用对象，不在刷新时反复建删页面。不做全屏转场。界面内存池固定为 32 KB；字体、样式或对象数变化后，必须在板上验证。按键只派发事件，网络和绘制不能阻塞按键回调。截图必须取自设备实际输出的像素块。

### 反向审查

检查：未知额度、零用量、超过 100%、已到重置时间、旧数据、断网、显示令牌失效，以及很大的 Token/费用。旧数据不能暗示账号到期；刷新不能把旧观察时间变成新时间。不以放大的效果图作为验收，应检查真实 240×320 像素、裁切和多次切页/切换额度视角后的运行情况。

## 实现决定

- 首页：上下两个平台仪表，每个平台内左右两列额度。
- 用量页：两个平台都保留今日与累计数据。
- 上下键切页；首页确认键切换已用/剩余；长按确认刷新，但不改上游数据时间。
- 静态、高对比呈现；颜色表达平台和数据状态，可读性不依赖动画。
